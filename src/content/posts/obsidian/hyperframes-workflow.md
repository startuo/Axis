> **一句话核心洞察**：AI 做视频的真正杠杆点不在于"更好的 prompt"，而在于**把人工参与降到零**——每一步能自动化就自动化，因为"在这样无痛的情况下，你会非常容易坚持下去"。

---

## 30 秒答案：工具生态 + 12 步管线 + 声音魔法

| 维度 | 核心内容 |
|---|---|
| **工具栈** | Codex（Agent）+ Hyperframes（HTML 视频）+ Remotion（React 视频）+ Claude Video（拆解）+ 剪映/火山引擎（TTS） |
| **管线** | 12 步：定规格 → 旁白 → 视觉风格 → 分镜 → 素材 → 配音 → 转写 → 组合 → 字幕 → 预览 → 验证 → 渲染 |
| **声音** | 全文最亮眼的环节：剪映生成→Codex 对标视频分析→处理后"非常完美" |
| **核心哲学** | 自动化一切——"自媒体创作能不用人工就不要用人工" |

## 一、工具生态的选型逻辑

### 1.1 两个视频引擎的分工

作者同时推荐 Hyperframes 和 Remotion，但它们的适用场景截然不同：

| | Hyperframes | Remotion |
|---|---|---|
| **技术栈** | HTML/CSS/JS | React/TypeScript |
| **适合场景** | 企业宣讲、数据动效、展示类视频 | 固定风格后的高度复制 |
| **代表案例** | 一次性精品视频 | "小Lin说"风格动画 + 口播 |
| **复用模式** | 每次可不同风格 | 风格固定后批量生产 |
| **学习曲线** | 低（HTML 即可） | 中（需 React） |

**选型逻辑**：
> 先确定视频是一次性的还是需要批量复制的——前者用 Hyperframes，后者用 Remotion。

这与 video-shotcraft 的设计完全吻合——Shotcraft 基于 Remotion 正是因为它要做"风格固定后的高度复制"。

### 1.2 两个辅助 Skill

| Skill | 角色 | 解决什么问题 |
|---|---|---|
| **Claude Video** | 结构拆解师 | 把对标视频拆成可复刻的结构化描述（前几秒怎么抓人、声音效果如何、旁白与画面的节奏） |
| **视频使用** | 导演大师 | 新手不知道该用什么工具时，它根据需求调用对应的工具链 |

**关键洞察**：两个 Skill 分别解决"知道要做什么"和"知道怎么做"——前者是分析能力，后者是执行能力。这是一个很好的 Skill 分工模式。

## 二、12 步视频制作流水线

```
1️⃣ 定规格       → 30s / 9:16 / 中文 / 知识类 / 图书介绍
2️⃣ 写旁白       → Codex 写 30s 中文旁白（不急着做画面）
3️⃣ 定视觉风格   → dark editorial / 深色背景 / 书封面主视觉
4️⃣ 做分镜       → 拆成 4-6 个画面段落，每段一句核心信息
5️⃣ 准备素材     → 书封面、标题、关键词、logo、BGM、配音文本
6️⃣ 生成配音     → Edge TTS / ElevenLabs / Hyperframes media
7️⃣ 转写配音     → 用最终音频转 transcript，不手动猜字幕时间
8️⃣ 创建 composition → index.html + data-start/data-duration/data-track-index
9️⃣ 做字幕       → 根据 transcript 自动同步
🔟 预览         → 先预览，不直接渲染
1️⃣1️⃣ 验证       → 报错、字体、布局溢出、字幕遮挡
1️⃣2️⃣ 渲染 MP4    → 确认无误后再渲染
```

### 管线设计的三个要点

**1. 先文字，后画面**：步骤 2 "先让 Codex 写旁白，不要急着做画面"——这个顺序非常重要。很多新手一上来就开始做画面，结果发现文案不行，画面全废。

**2. 转写代替手动对齐**：步骤 7 "用最终音频转 transcript，不手动猜字幕时间"——这一步省掉了最枯燥的人工操作。

**3. 预览在渲染前**：步骤 10-11 的验证环节——渲染是昂贵的（时间和算力），在渲染前把所有问题找出来。

## 三、声音处理：全文最精妙的环节

这是全文技术含量最高、也是读者反馈最好的部分。

### 3.1 问题：中文 TTS 的"AI 味"

> ElevenLabs 英文声音完美，但中文读起来有很多错字——已经不是 AI 味的问题了，是根本没法用。

这是一个被严重低估的现实：**英文 TTS 已经很成熟，但中文 TTS 仍然是一个痛**。

### 3.2 解决方案：Codex 作为声音工程师

```
剪映生成原始语音 MP4
        ↓
喂给 Codex + 对标视频的声音
        ↓
Codex 分析对标视频的声音参数
        ↓
对照原始 MP4 进行参数调整
        ↓
输出：自然、有磁性、有故事感的声音
```

**两个操作路径**：
1. **精确法**：发参数截图给 Codex → Codex 按照参数处理
2. **直觉法**：直接放对标视频 → 告诉 Codex "我想要这样的声音" → Codex 自动对标

### 3.3 可迁移到多种视频类型

一旦掌握了声音处理能力，可以复用到：
- 电影讲解 / 故事讲解
- 生活哲理类
- 科普类账号

**本质上是一种"声音风格迁移"能力**——用对标视频的声音作为参考，把自己的 TTS 调整到接近的质感。

### 3.4 未完成的自动化

> 其实这部分也应该用自动化的方式会比较好。所以后面我会尝试用火山引擎的 API，让 Codex 自动去做旁白和声音的 TTS 文件。

**目标状态**：Codex 直接调用 TTS API → 自动处理声音参数 → 输出成品音频，完全跳过剪映手动导出这一步。

## 四、"去 AI 味"的文案方法论

这是文章中另一个实用价值极高的部分。

### 4.1 信息收集三通道

```
1. Codex 收集图书信息（事实层）
2. 微信读书 Skills → 划线 + 评语（社交验证层）
3. Codex 搜索著名书评（权威背书层）
```

三层信息叠加 → 再让 Codex 基于事实写旁白。**"基于事实"是去 AI 味的前提——AI 编的东西一眼假。**

### 4.2 三条去 AI 味规则

| 规则 | 示例 | 为什么 |
|---|---|---|
| **不要"不是……而是……"** | ❌ "这不是一本普通的书，而是一把钥匙" | 这是 AI 最典型的句式模板 |
| **避免排比感太强** | ❌ "它让你思考，让你成长，让你蜕变" | 三连排比 = AI 签名 |
| **平铺直叙不傲慢** | ✅ "这本书讲了这样一个故事……" | 自然讲述 > 居高临下的推荐 |

### 4.3 把拆解结果变成可复用的 Skill

> 这一次用 Codex 从书籍收集到整理的内容形成一个 Skills。这样以后旁白的文案都是可以复用的。

**这是一个关键的工程化思维**：不是每次重新写 prompt，而是把验证有效的方法封装成 Skill。这与 yao-geo-skills 的 Skill 工厂模式 是同一个逻辑。

## 五、Codex 自主迭代：画面与字幕对齐

### 5.1 "完全没有插手"的自动化环节

> 这个时候我完全没有插手，因为 Codex 现在已经有了一个大概的方案。之前我已经喂给它一个对标视频，现在也有了旁白和旁白的语音，Codex 会自己进行视频创作。

**三步前置准备是做对了的事**：
1. 喂对标视频 → Codex 知道目标长什么样
2. 准备好旁白文本 → Codex 有内容素材
3. 准备好旁白语音 → Codex 有音频素材

有了这三样，Codex 就有了**自主创作的完整上下文**。

### 5.2 两类典型返工 + 修复循环

| 问题类型 | 修复方式 | 通常耗时 |
|---|---|---|
| **语音字幕对不上** | Codex 自动抽帧检查 → 分析为什么对不上 → 调整 | 约 2 轮 |
| **画面问题**（内容、字幕位置、形态） | 反复沟通 → 不断提醒靠近对标视频 | 视复杂度而定 |

> 整个流程理顺之后，就可以生成复刻程度比较高的视频了。

## 六、与现有知识体系的连接

### 6.1 与 video-shotcraft 的对比

两者都是基于 Remotion（或 HTML）的 AI 视频制作，但路径不同：

| | video-shotcraft | Codex + Hyperframes 工作流 |
|---|---|---|
| **知识来源** | 106 张配方卡（已编码的专业知识） | 拆解对标视频（每次重新分析） |
| **适用阶段** | 成熟期：有固定风格的批量生产 | 探索期：拆解和学习不同风格 |
| **自动化程度** | 高：Agent 自动选卡 → 适配素材 | 中：首次需人工拆解，后续可复用 |
| **声音处理** | 40+ 分类 SFX + 钉帧管理体系 | Codex 对标分析 + 参数调校 |

**两者可以结合**：用 Codex + Claude Video 拆解对标视频 → 沉淀为配方卡式的 Skill → 用 Remotion 批量复制。

### 6.2 12 步管线与 video-shotcraft 的八阶段对比

| video-shotcraft 阶段 | Codex + Hyperframes 步骤 | 类比 |
|---|---|---|
| 阶段 0：产品理解 | 步骤 1–3：定规格/旁白/视觉 | 先锁定方向 |
| 阶段 3：分镜设计 | 步骤 4：timestamp 分镜 | 功能→镜头映射 |
| 阶段 4：最终素材采集 | 步骤 5–7：素材/配音/转写 | 按分镜准备 |
| 阶段 5：逐镜头实现 | 步骤 8–9：composition + 字幕 | 落地执行 |
| 阶段 7：验收 | 步骤 10–12：预览/验证/渲染 | 质量门禁 |

**两者用了同一套生产管线逻辑**——只是 video-shotcraft 把管线写进了 `pipeline.md`，Codex 工作流把这套管线内化在 Agent 的执行过程中。

### 6.3 自动化哲学 = Dynamic Workflows

> 自媒体创作能不用人工就不要用人工。在这样"无痛"的情况下，你会非常容易坚持下去。

这完美呼应了 [Dynamic Workflows](/posts/obsidian/dynamic-workflows/) 的核心论点：**杠杆点不在"写出更好的 prompt"，而在"设计一个能持续运行的系统"**。

"无痛"这个词是关键——很多人放弃不是因为做不出来，是因为每做一次要克服太多人工摩擦。**自动化不只是效率问题，更是"坚持"问题。**

### 6.4 与抖音万粉复盘的呼应

上一篇文章 [抖音万粉复盘](/posts/obsidian/douyin-growth/) 讲的是"找到对的方向然后多发"，这篇文章讲的是"把对的方向上的单条视频成本降到零"。两者是同一策略的两个维度：

```
万粉复盘：策略层 → 方向选择 + 爆款概率
本文：    执行层 → 将单条视频的人工参与归零
```

## 七、核心设计洞察

### 7.1 "对标视频"是隐形的 Recipe Card

> 我已经喂给它一个对标视频，现在也有了旁白和旁白的语音，Codex 会自己进行视频创作。

对标视频在 Codex 工作流中扮演的角色，与 video-shotcraft 中的配方卡一模一样——**它是"目标状态"的结构化描述**。区别在于：
- 配方卡是人类从经验中提炼出来的结构化知识
- 对标视频是 AI 通过 Claude Video 自己分析出来的结构化描述

**但最终目标相同**：给 Agent 一个精确的"要做成什么样"的参照。

### 7.2 信息收集的"三层验证"

```
事实层（Codex 抓取） → 社交验证层（微信读书划线） → 权威层（著名书评）
```

这种三层信息叠加不是简单的"多找点资料"——每层解决不同的问题：
- 事实层 → 确保不编造
- 社交验证层 → 确保说到读者心坎里
- 权威层 → 确保有深度和可信度

### 7.3 "去 AI 味"的本质 = 去模板化

三条去 AI 味规则——禁"不是而是"、禁排比、禁傲慢口吻——本质上都是在**打破 AI 的语言模板**。AI 的默认输出有高度可预测的句式模式，去 AI 味就是系统地识别和禁用这些模式。

这与 video-shotcraft 中"物理隐喻替代抽象描述"是同一个逻辑——**用具体替代抽象，用自然替代模板。**

## 八、可立即使用的操作清单

### 如果你想复刻这套工作流：

- [ ] **装工具**：Codex + Hyperframes + Remotion + Claude Video Skill + 视频使用 Skill
- [ ] **找对标**：找一个你想复刻风格的抖音视频（30 秒以内）
- [ ] **拆结构**：用 Claude Video 拆解对标视频（开头怎么抓人、节奏、声音、画面）
- [ ] **写旁白**：基于事实写 30 秒旁白（去 AI 味：禁"不是而是"、禁排比、禁傲慢）
- [ ] **处理声音**：剪映生成 TTS → 喂 Codex + 对标视频 → Codex 调参数
- [ ] **做分镜**：旁白拆成 4-6 段 → 每段配一个画面
- [ ] **自动生成**：把分镜 + 旁白 + 音频 + 对标视频全喂给 Codex → 让它自主创作
- [ ] **迭代**：语音字幕对齐约 2 轮 → 画面调整多轮 → 预览 → 渲染
- [ ] **沉淀 Skill**：把验证通过的流程封装成可复用的 Skill

## 总结

这篇文章最珍贵的不是工具清单或步骤列表，而是一个**完整的自动化哲学**：

> 1. **能不用人工就不用人工**：不是懒，是只有"无痛"才能坚持。
> 2. **对标视频是 AI 的坐标系**：有了精确的参照，AI 才能自主创作而不跑偏。
> 3. **去 AI 味 = 去模板化**：识别 AI 的句式签名，然后系统性地禁用它们。
> 4. **一次做成 → 封装成 Skill → 无限复用**：这才是自动化真正的杠杆。
> 5. **最大的障碍不是技术，是"还没有去行动"**：用自然语言跟 Codex 聊天，一步一步找到解决办法。

> **一句话带走的实践原则**：找一个对标视频，用 Claude Video 拆结构，Codex 写去 AI 味的旁白，剪映做 TTS 后让 Codex 对标处理声音，Hyperframes 做画面——把第一次做成后封装为 Skill，以后每次都是零人工。无痛 = 可持续 = 真正的竞争力。
