> **一句话核心洞察**：这不是一本设计参考手册——这是把网页设计的**全部专业知识编码为 80 个标准化的 AI 提示词卡片**。每个词条遵循"概念→场景→提示词"的配方卡格式，让 AI 从不稳定的"高级感"猜测变为精确的结构化执行。

## 一、这本词典的本质：知识编码系统

### 1.1 为什么需要视觉词典？

> 很多人让 AI 做网页时只会说"帮我做一个高级、简洁、有设计感的网站"。问题在于——"高级""简洁""有设计感"都不是明确的网页结构。

**本质问题**：抽象形容词 → AI 随机猜测 → 结果不可预测 → 反复修改 → 挫败。

**视觉词典的解法**：80 个精确术语 × 每个术语 = `概念说明 + 适用场景 + 可直接复制的 AI 提示词`。

### 1.2 配方卡格式

与 video-shotcraft 的 106 张镜头配方卡 完全同构：

| video-shotcraft 配方卡 | Vibe Coding 视觉词典 |
|---|---|
| 卡名（`spotlight-hero-card`） | 术语（`Split-screen Hero`） |
| 一句话描述 | 概念说明 |
| 适用场景 | 适用场景 |
| 参数表 + 已知坑 | 可直接复制的 AI 提示词（含具体 CSS 属性、断点、行为约束） |
| 参考实现 | 无（提示词本身就是实现指令） |

**关键差异**：video-shotcraft 的卡片是给 AI 读的"怎么做"，视觉词典的卡片是给**人读的"怎么告诉 AI"**。前者是 Agent 的内部知识，后者是人→Agent 的通信协议。

### 1.3 三要素的精确设计

每个词条严格遵循三要素格式：

| 要素 | 功能 | 示例（#1 卡片式布局） |
|------|------|---------------------|
| **概念说明** | 建立共同语言——这是什么 | "把内容拆成独立卡片，边界清楚，浏览速度快" |
| **适用场景** | 帮人判断什么时候用 | "作品集、博客列表、功能介绍、商品列表" |
| **AI 提示词** | 可复制粘贴的精确指令 | "桌面端三列，平板端两列，手机端单列；米白背景、深绿色强调色、细边框、克制圆角和轻微阴影" |

**第三条尤其重要**：提示词不是"用卡片布局"——而是把颜色、列数、圆角、阴影全部具体化。**把审美决策从 AI 手里拿回来，变成精确的工程参数。**

## 二、八章的深层逻辑：从结构到灵魂

### 2.1 上下篇的分工

```
上篇（1-40）：骨架 + 功能
  布局 → 结构 → 导航 → 组件
  "这个网站能正常工作吗？"

下篇（41-80）：节奏 + 气质
  动作 → 反馈 → 风格 → 高级效果
  "这个网站有灵魂吗？"
```

上篇确保**可用性**，下篇确保**品味**。先骨架后灵魂——不能在布局还没定的时候就纠结玻璃拟态的透明度。

### 2.2 每章的核心洞察

| 章节 | 最关键的洞察 |
|------|-------------|
| **布局**（#1-10） | 10 种布局覆盖所有网页需求——从卡片到瀑布流到 Bento Grid，没有哪种是"万能"的 |
| **结构**（#11-20） | 页面结构和布局是两回事——结构回答"先看到什么"，布局回答"怎么排列" |
| **导航**（#21-30） | 导航不只是"放几个链接"——Sticky/汉堡/面包屑/锚点/标签各有精确的适用场景 |
| **组件**（#31-40） | 每个组件提示词都包含**可访问性约束**（aria-label、focus 管理、键盘操作）——这不是附加项，是内置在提示词里的 |
| **动作**（#41-50） | 每个动画提示词都包含 `prefers-reduced-motion` 的回退方案——"动效不能成为完成任务的必要条件" |
| **反馈**（#51-60） | 加载/空/错/重试/成功——五种状态覆盖**每一个交互的生命周期** |
| **风格**（#61-70） | 极简/编辑/瑞士/玻璃/野兽派/深色——每种风格都有**精确的颜色、字体、阴影约束** |
| **高级**（#71-80） | "高级效果不等于更复杂"——每个高级效果都有**性能预算和不支持时的降级方案** |

## 三、两条完整的提示词：从词汇到组合

文章结尾提供了两条可直接复制给 AI 的**完整网页提示词**——它们不是"把所有词条堆在一起"，而是经过编排的**结构化指令**。

### 3.1 上篇提示词的结构

```
[人物设定]：为 Punk 设计个人作品网站
[页面结构]：Home、Work、Project Detail、About、Journal、Contact
[布局指令]：Split-screen Hero → Bento Grid → Card Layout → Masonry Gallery
[导航指令]：Sticky Navbar → Hamburger Menu → Breadcrumb → Anchor Links
[组件指令]：Modal Contact → Lightbox → Toast → Accordion → Command Palette
[视觉约束]：米白+深绿+黑 / 低饱和抽象图形 / 禁家居/办公桌/图库人物/卡通
[技术约束]：Mobile-first / 语义化 HTML / 键盘可访问 / prefers-reduced-motion / Lazy Loading
```

### 3.2 下篇提示词的结构

```
[动作指令]：Scroll Reveal / Horizontal Scroll + Snap / Infinite Scroll / Marquee
[反馈指令]：Skeleton → Lazy Loading → Spinner → Progress Bar → Loading Button → Empty → Error → Optimistic UI → Inline Validation
[风格约束]：Minimalism + Editorial / 米白+黑+深绿 / 克制的 Glassmorphism / 轻 Grain Texture
[高级效果]：Custom Cursor / Magnetic Button / 3D Tilt / Clip-path Reveal / Three.js（含回退）
[可访问性]：全套 prefers-reduced-motion / 键盘 / 屏幕阅读器
[性能预算]：JS ≤170KB gzip / 字体 ≤2 家族 / WebGL 延迟加载
```

### 3.3 组合的工程智慧

完整提示词不是 80 个词条的罗列——它做了三件事：
1. **选择**：只选适合"Punk 个人网站"的词条（不是全部 80 个）
2. **排序**：按"骨架→功能→节奏→气质"排列，而不是按章节顺序
3. **否定约束**：明确说了"不要什么"——禁家居产品/办公桌/图库人物/卡通/皮衣/朋克视觉

**否定约束的价值**：告诉 AI "不要什么"比"要什么"更能防止它跑偏——因为 AI 的默认审美倾向这些被禁的元素。

## 四、与知识体系的深度连接

### 4.1 配方卡范式的三次出现

这是配方卡模式在你的知识库中的第三次出现：

| 项目 | 领域 | 卡的内容 | 面向 |
|------|------|---------|------|
| video-shotcraft | 视频动效 | 106 张镜头配方卡（参数+已知坑+demo） | AI Agent |
| yao-geo-skills | GEO 优化 | 21 个 Skill（SKILL.md+manifest+evals） | AI Agent |
| **Vibe Coding 视觉词典** | 网页设计 | 80 个词条（概念+场景+提示词） | 人→AI Agent |

**三者构成完整的范式光谱**：
- video-shotcraft：AI **内部**知识（给 Agent 读的怎么执行）
- yao-geo-skills：AI **接口**知识（Agent 的调用契约和质量门禁）
- 视觉词典：人→AI **通信**知识（人怎么精确告诉 AI 做什么）

### 4.2 与 Prompt 工程体系的呼应

视觉词典的"概念→场景→提示词"三要素，与 David Max #8 UI 组件 Prompt 的"五态模型"互补：

| David Max #8 | 视觉词典 |
|---|---|
| 定义**一个组件**的所有状态 | 定义**整个页面**的所有结构和风格 |
| Loading/Empty/Error/Ideal/Edge | 布局/结构/导航/组件/动作/反馈/风格/高级 |
| 纵向深度（一个组件的完整生命周期） | 横向广度（一个网页的全部知识域） |

### 4.3 对 SEO/GEO 的延伸

视觉词典中每个词条的"概念说明"隐含了一个重要的 SEO/GEO 维度：**语义化 HTML**。几乎所有提示词都要求使用正确的 HTML 元素（`button`/`nav`/`dialog`/`section`）和 ARIA 属性——这恰好是 yao-geo-skills 的页面技术层 关注的核心：**让 AI 搜索能正确解析和抽取页面内容**。

> 好的网页设计 + 语义化 HTML = 天然的 GEO 优化。不需要事后补救。

## 五、可迁移的设计模式

### 5.1 "概念→场景→提示词"三要素公式

这是一个**通用的知识编码公式**，可以迁移到任何需要"人→AI 精确沟通"的领域：

```
[术语名称]
概念：一句话说清楚这是什么（建立共同语言）
场景：什么时候用它、什么时候不用它（防止误用）
提示词：可直接复制给 AI 的精确指令（含参数、约束、边界）
```

### 5.2 否定约束系统

视觉词典的提示词中大量使用了否定约束：

| 类型 | 示例 |
|------|------|
| **禁元素** | "不要使用家居产品、办公桌摆拍、商业图库人物或卡通插画" |
| **禁效果** | "不要做成平均九宫格"、"不要把每段内容都放进卡片" |
| **禁行为** | "不要劫持整个页面滚动"、"不要把所有资源都延迟加载" |
| **禁风格** | "不要自动使用皮衣、莫霍克发型、涂鸦、铆钉"（Punk 是人名不是朋克风格） |

**否定约束是最被低估的 Prompt 工程技巧**——AI 的默认行为有强烈的模式倾向，否定约束是唯一可靠的纠偏方式。

### 5.3 可访问性内建原则

**没有一个词条把可访问性作为"额外加分项"——它们把可访问性内置在提示词里**：
- 按钮 = `aria-expanded` + `aria-controls`
- 导航 = `nav aria-label` + `focus-visible`
- 动画 = `prefers-reduced-motion` 回退
- 表单 = `role="alert"` + 焦点管理

> 可访问性不是"做完再加"——它在提示词里就是默认的。

### 5.4 Punk 作为"约束锚点"

全文所有 80 个词条 + 两条完整提示词都围绕同一个虚构人物 **Punk**（网页设计师）展开。这不是巧合——**一个具体的 Persona 是提示词精确性的锚点**。

> "为 Punk 设计个人网站"比"设计一个个人网站"精确得多——因为 Punk 有明确的设计品味约束（米白+深绿、编辑风、不朋克），AI 不会随机选择风格。

## 六、可立即使用的操作清单

- [ ] 在下一次让 AI 做网页时，用视觉词典中的**精确术语**替换"高级感""简洁"等模糊形容词
- [ ] 为你的项目创建一个"否定约束清单"——明确告诉 AI **不要**用什么元素/风格/行为
- [ ] 给 AI 的网页提示词中，**内置** prefers-reduced-motion 回退 + 键盘可访问性 + 语义化 HTML
- [ ] 将你的项目中常用的布局/组件/风格组合封装成类似视觉词典的"概念→场景→提示词"卡片
- [ ] 与 David Max #8 UI 组件 Prompt 配合使用——视觉词典定整体风格，David Max #8 定单个组件质量

## 总结

Vibe Coding 视觉词典本质上是一套**网页设计的 AI 通信协议**：

1. **结构化**：80 个词条 × 三要素（概念+场景+提示词）= 可搜索、可组合的知识系统
2. **精确化**：每个提示词包含断点、颜色、CSS 属性、列数——不给 AI 留"猜"的空间
3. **约束化**：否定约束（"不要 X"）比正向描述更能防止 AI 跑偏
4. **内建质量**：可访问性、响应式、性能——不是附加项，是提示词的一部分
5. **Persona 锚定**：一个具体的人物设定让风格决策有据可依

> **一句话带走的实践原则**：给 AI 做网页设计时，把你要的每个元素翻译成"概念（是什么）+ 场景（什么时候用）+ 精确参数（CSS 属性、断点、颜色、行为约束、否定约束）"。模糊的形容词 = AI 的随机猜测 = 返工的起点。
