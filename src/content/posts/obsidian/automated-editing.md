> **一句话核心洞察**：自动化的真正价值不是"AI替你创作"，而是**把"爆款拆解→素材匹配→配音对齐→草稿输出"的重复劳动从2小时压缩到20分钟**。这套工作流的底层逻辑是"抄爆款"——让Codex代替你完成80%的机械操作，你把精力留给审核和调优。

---

## 30 秒答案

| 维度 | 核心内容 |
|---|---|
| **目标** | 5倍效率提升：从每天6条 → 30条带货视频 |
| **底层逻辑** | 抄爆款——参考爆款视频的结构和节奏，替换为自己的素材 |
| **适用场景** | 电商带货、营销混剪、Vlog拼接；不适用高精度原创 |
| **技术栈** | Codex + FFmpeg + Python + 豆包TTS/VoxCPM + 剪映 |
| **核心流程** | 拆解→匹配→配音→草稿，4步走完 |

---

## 一、工作流的底层逻辑

### 1.1 抄爆款方法论

> 不管是做内容还是做电商，想要快速获得流量，最简单的办法就是**抄爆款**。爆款都是经过市场验证的内容，只要跟得够快，流量不会太差。

这套工作流的本质是**结构复制**，而不是内容复制：

| 维度 | 传统的"抄" | 这套工作流的"抄" |
|------|-----------|-----------------|
| 抄什么 | 抄内容、抄话术（可能侵权） | 抄**节奏和结构**（镜头长度、转场位置、能量曲线） |
| 结果 | 可能被限流/下架 | 完全原创画面 + 相同节奏 |
| 效率 | 2-3小时/条 | 20分钟/条（首次）→ 5分钟/条（封装Skill后） |

### 1.2 与传统做法的对比

| 维度 | 传统做法 | 这套工作流 |
|------|---------|-----------|
| 时间 | 2-3小时/条 | 20-30分钟/条 |
| 日产量 | 6条（极限） | 30条（轻松） |
| 核心工作 | 手动找素材、卡时间、对字幕 | 审核、微调、决策 |
| 瓶颈 | 人的注意力 | 素材库的丰富度 |

> 效率提升的逻辑不是"AI比人聪明"，而是"AI替人跑完80%的机械步骤，人只做最后的判断和打磨"。

### 1.3 定位说明

这套工作流的定位是**自动化生产，不是精品创作**。

| 适合 | 不适合 |
|------|--------|
| 电商带货视频 | 高精度原创内容 |
| 营销混剪 | 复杂转场和情绪表达 |
| Vlog拼接 | 精细镜头语言 |
| 多段素材拼接 | 需要情感叙事的视频 |

**原因**：自动化的匹配逻辑目前还做不到那么精准的语义理解和情绪把控。

## 二、工作流前置准备

### 2.1 工具清单

| 工具 | 用途 | 获取方式 |
|------|------|---------|
| **Codex** | 核心Agent，调度整个流程 | 需提前安装 |
| **FFmpeg** | 视频拆分、合成、格式转换 | 基础依赖 |
| **Python 3.8+** | 运行自动化脚本 | opencv-python, numpy, pillow |
| **豆包 TTS** | 稳定AI配音 | 付费，约0.4-0.8元/分钟 |
| **VoxCPM** | 免费声音克隆（可选） | GitHub开源 |
| **剪映专业版** | 最终草稿编辑 | 免费 |

### 2.2 一键环境检查提示词

```
请帮我检查视频自动化剪辑需要的环境：

检查完之后，告诉我哪些已经装好了，哪些需要我手动处理。
```

### 2.3 文件夹结构规范

```
项目文件夹/
├── AGENTS.md           # 项目配置文件（核心）
├── assets/             # 素材库（按类别分类）
│   ├── 外观/
│   ├── 功能/
│   ├── 场景/
│   ├── AI生成/
│   └── 真人实拍/
├── work/               # 工作区
│   └── YYYY-MM-DD/     # 每次剪辑独立文件夹
│       ├── reference-YYYY-MM-DD.mp4
│       ├── video_clips/
│       ├── script.txt
│       ├── material/
│       │   ├── fragment01/
│       │   └── fragment02/
│       ├── voice/
│       └── jianying_draft/
└── final/              # 最终成品
```

**关键设计原则**：
- `assets/` 里的素材只**复制**不**移动**，保护原始素材库
- `work/` 按日期隔离，避免多任务混淆
- `AGENTS.md` 是Codex理解项目需求的长期上下文

## 三、四步核心流程

### 3.1 第一步：拆解参考视频

**目标**：把参考视频拆成独立镜头，提取关键帧，生成结构数据。

**输入**：爆款参考视频（下载后放入 `work/YYYY-MM-DD/`）

**操作提示词**：

```
我需要拆解一个参考视频。

参考视频位置在@（输入你的文件名，Codex会自动搜索）

请帮我完成这几件事：
1. 用 FFmpeg 识别视频的镜头切换点（通过帧间差异分析）
2. 为每个镜头提取关键帧，保存为图片
3. 提取视频的音轨，单独保存
4. 生成一个 recipe.json 文件，记录每个镜头的开始时间、结束时间、时长、关键帧路径
5. 如有文案，根据音频生成一个配音文本，按镜头分段，文案需要精校，避免出错

完成后按照AGENTS.md要求，保存到对应文件夹，并告诉我识别了多少个镜头，让我确认切分是否合理。
```

**产出**：
- `video_clips/` → 每个镜头的视频片段
- `recipe.json` → 镜头的结构化数据（开始/结束/时长/关键帧路径）
- `script.txt` → 按镜头分段的配音文本（需人工精校）

**核心逻辑**：把参考视频的结构（镜头顺序、时长、节奏）"提取"为机器可读的JSON文件，后续所有操作都基于这个JSON。

---

### 3.2 第二步：筛选和匹配素材

**目标**：从素材库中为每个镜头找到视觉最匹配的素材。

**输入**：`recipe.json` + `assets/` 素材库

**操作提示词**：

```
我需要从素材库中匹配替换素材。

项目信息：
- recipe.json 路径：(上一步的拆解路径)/recipe.json
- 素材库路径：assets/
- 输出路径：work/（你的保存路径）

匹配要求：
1. 读取 recipe.json 中每个镜头的关键帧
2. 遍历素材库，为每个素材提取关键帧
3. 通过颜色、亮度、构图等视觉特征，为每个镜头推荐最匹配的素材（给出置信度得分）
4. 应用这些规则：
   - 避免连续3个镜头都用同一个素材
   - 避免相邻镜头出现明显重复的房间或构图
5. 生成 fragment_plan.json 和 matches.json
6. 把选中的素材复制（不是移动）到 material/fragment01/, fragment02/ 等文件夹

重要原则：如果某个镜头的匹配置信度低于 0.6，标记为"缺素材"，不要用无关素材硬凑。

完成后，告诉我匹配结果，并列出哪些镜头缺素材需要人工补充。
```

**匹配逻辑**：
1. Codex读取参考视频每个镜头的关键帧
2. 遍历素材库，为每个素材也提取关键帧
3. 通过颜色、亮度、构图计算视觉相似度
4. 生成匹配得分，推荐最高分素材

**关键原则**：

> 宁可留空素材，也不要用无关素材硬凑。如果某个镜头的匹配置信度低于 0.6，标记为"缺素材"，不要用无关素材硬凑。

**产出**：
- `fragment_plan.json` → 每个镜头的素材需求（场景、动作、景别）
- `matches.json` → 每个镜头的匹配结果（素材路径、置信度、是否降级）
- `material/fragmentNN/` → 选中的素材（复制）

**人工检查点**：查看匹配结果，不满意的镜头手动替换或让Codex重新匹配。

---

### 3.3 第三步：生成配音

**目标**：为视频生成配音，并记录每段配音的实际时长。

**输入**：精校后的 `script.txt`

**操作提示词**：

```
我需要为视频生成配音。配音文本是@（你的文案.txt）

要求：
1. 调用豆包 TTS 接口，为每个镜头生成独立的语音文件
2. 读取每个生成的语音文件的实际时长
3. 如果配音时长和参考视频的镜头时长不一致，记录时长差异
4. 将所有片段拼接成完整的配音文件：final_voice.mp3
5. 更新 recipe.json，记录真实的配音时长

完成后，让我试听一遍，确认语音自然度和语速。
```

**配音时长对齐逻辑**：

| 情况 | 处理方式 |
|------|---------|
| 配音时长 < 参考镜头时长 | 画面保持参考时长，配音加速（保持音调） |
| 配音时长 > 参考镜头时长 | **画面拉长到配音时长**——如果配音读了5秒，镜头就占5秒 |
| 参考无配音（纯音乐） | 跳过配音生成，保留音乐 |

> 以配音时长为基准，画面和字幕都跟着配音走——这与传统剪辑"先剪画面再配音"的顺序正好相反，是自动化工作流的关键设计。

**产出**：
- `voice/final_voice.mp3` → 完整配音文件
- 更新后的 `recipe.json`（记录了真实配音时长）

**人工检查点**：试听配音，确认自然度和语速。

---

### 3.4 第四步：生成样稿和剪映草稿

**目标**：根据匹配结果和配音，自动生成预览视频和剪映草稿。

**输入**：`recipe.json` + `matches.json` + `material/` + `voice/final_voice.mp3`

**操作提示词**：

```
我需要生成最终的视频和剪映草稿。

输入信息：
- recipe.json：work/recipe.json
- matches.json：work/matches.json
- 素材路径：work/material/
- 配音文件（可选）：work/voice/final_voice.mp3
- 字幕文本（可选）：work/script.txt

输出：
1. 渲染预览视频：work/remix.mp4
2. 字幕文件：work/captions.srt
3. 剪映草稿：work/jianying_draft/

要求：
1. 按照 recipe.json 和 matches.json，把素材按顺序拼接
2. 如果有配音，用配音的时长作为基准；否则用参考视频的时长
3. 生成 .srt 格式的字幕文件
4. 生成剪映可以打开的草稿格式，注意：
   - 内容 ID、元数据 ID、根索引 ID 必须一致且唯一
   - 素材路径必须是绝对路径且文件真实存在
   - 所有素材先复制到项目文件夹，避免路径失效

直接生成剪映草稿，完成后提醒我审核和确认。
```

**剪映草稿的三个坑**（踩过多次的教训）：

| 坑 | 表现 | 解决方案 |
|---|------|---------|
| **ID不一致** | 草稿打开报错或覆盖旧草稿 | 内容ID、元数据ID、根索引ID必须一致且唯一 |
| **路径失效** | 草稿打开显示"素材丢失" | 素材路径必须是**绝对路径**，文件必须真实存在 |
| **素材重复** | 剪映显示"素材已存在" | 所有素材先复制到项目文件夹，避免引用外部路径 |

**产出**：
- `remix.mp4` → 预览视频
- `captions.srt` → 字幕文件
- `jianying_draft/` → 可打开的剪映草稿文件夹

**审核清单**（打开剪映检查）：
1. ☐ 草稿能正常打开吗？
2. ☐ 所有素材都能正常显示吗？
3. ☐ 时间轴顺序和时长与预期一致吗？
4. ☐ 字幕位置正确、不遮挡关键内容吗？
5. ☐ 配音和画面同步吗？

## 四、封装为Skill

> 最关键的一步：**跑通整个工作流以后，直接跟Codex说：帮我把工作流封装成Skill。**

一次封装，永久复用。下次只需：
1. 准备好素材
2. 选择参考视频
3. 调用Skill
4. 审核成果

**封装后的使用流程**：
- **首次搭建**：30分钟（环境+文件结构+Skill封装）
- **日常使用**：5-10分钟/条（选参考视频 + 审核输出）

## 五、AGENTS.md 项目配置文件

> 这是整个工作流的"宪法"——所有自动化的决策都基于此文件。

### 5.1 完整模板

```markdown
# AGENTS.md

## 目标

一句话说明这个项目要完成什么。

## 目录

项目根目录只保留稳定结构，单次剪辑产生的过程文件放进当日工作文件夹。

- `AGENTS.md`：项目长期上下文，记录目标、目录、流程、输出和验收标准。
- `assets/`：提前准备好的产品素材、场景素材、人物素材、AI 片段和其他可复用素材。剪辑时只从这里复制素材，不移动或破坏原文件。
- `work/`：正在制作或待审核的视频项目。每次剪辑在这里创建一个当日工作文件夹。
- `final/`：已经完成并确认通过的视频，从 `work/` 迁移到这里，避免工作区文件过多。

每次剪辑时，在 `work/` 下创建一个当日工作文件夹：

```
work/
  YYYY-MM-DD/
    reference-YYYY-MM-DD.mp4
    video_clips/
    script.txt
    material/
      fragment01/
      fragment02/
    voice/
    jianying_draft/
```

当日工作文件夹说明：

- `reference-YYYY-MM-DD.mp4`：用户提供的完整参考视频，作为整体顺序、节奏、时长、音频和拆解依据。
- `video_clips/`：自动拆解参考视频后得到的画面片段和参考帧，用作视觉顺序和素材匹配依据。
- `script.txt`：从参考视频、用户文案、口播稿或配音文件整理出的口播/字幕/配音文本。
- `material/fragmentNN/`：从 `assets/` 筛选并复制过来的当前片段候选素材或已批准素材。
- `voice/`：按片段生成的配音、清理后人声、分段语音和拼接后的成品音频。
- `jianying_draft/`：当前样稿对应的剪映草稿、草稿检查报告和必要备份。

## 流程

读取参考视频 → 拆分参考画面 → 提取文案/配音文本 → 筛选原始素材 → 生成配音 → 生成样稿和剪映草稿

1. 读取参考视频：在 `work/YYYY-MM-DD/` 下创建当日工作文件夹，将用户提供的参考视频保存为 `reference-YYYY-MM-DD.mp4`。
2. 拆分参考画面：使用自动镜头切分和关键帧抽取拆解参考视频，片段和参考帧保存到 `video_clips/`，结构数据保存在当日工作文件夹。
3. 提取文案/配音文本：从参考音频、用户文案或配音文件中整理口播文本，保存为 `script.txt`。
4. 筛选原始素材：读取 `assets/`，用参考帧和素材抽帧做视觉匹配，候选结果保存到当日工作文件夹，通过的素材复制到 `material/fragmentNN/`。
5. 生成配音：默认使用豆包语音模型生成新配音，分段语音和合成音频保存到 `voice/`。
6. 生成样稿和剪映草稿：用筛选素材和新配音生成样稿，并创建剪映草稿保存到 `jianying_draft/`，供用户打开审核。

## 输出

- 视频比例：9:16 竖屏。
- 分辨率：1080x1920。
- 帧率：60fps。
- 文件命名规则：`YYMMDD-platform-product-序号.mp4`，英文缩写优先。
- 默认审核方式：生成剪映草稿，供用户打开审核。
- 默认归档方式：用户确认通过后，从 `work/` 迁移到 `final/`。

## 验收

视频合格标准：

- 每个视觉片段都有可用素材；缺素材和低置信度片段必须明确暴露。
- 不用无关素材硬凑数量。
- 素材画面和产品、场景、动作、景别、角度、光线、产品可见度和构图基本匹配。
- 复制素材，不移动或破坏原始素材。
- 识别重复素材，不能把不同文件名当成不同内容。
- 三个连续镜头范围内尽量避免同一来源文件夹重复出现。
- 相邻片段避免明显重复的构图或语义场景。
- 有关联的 AI 片段或同一角色片段要保持身份连续。
- 成片视觉速度保持 `1.00x`，除非用户明确要求变速；短素材可定格补足，不通过变速硬拉。
- 成片比例、分辨率和帧率符合本文件的通用配置。
- 字幕必须在所属片段内，按语义断句，不机械凑字数。
- 字幕不遮挡产品主体、关键动作或重要信息。
- 如果使用配音，以真实成品配音时长为画面和字幕依据。
- 如生成剪映草稿，必须是新建可编辑草稿，不能覆盖原生或加密缓存。
- 剪映草稿的内容 ID、元数据 ID 和根索引 ID 必须一致，批量草稿 ID 不能重复。
- 剪映草稿的素材路径必须存在，媒体源范围不能超过真实时长。
```

### 5.2 AGENTS.md 的关键作用

## 七、核心设计洞察

### 7.1 以配音为时间基准

传统剪辑：先剪画面 → 再配声音 → 再对字幕

这套工作流：先配声音 → 画面根据声音时长调整 → 字幕自动对齐

**优势**：避免了"画面剪好了发现配音时长对不上"的返工。

### 7.2 置信度阈值（0.6）是质量控制的关键阀门

> 如果某个镜头的匹配置信度低于 0.6，标记为"缺素材"，不要用无关素材硬凑。

没有这个阀门，AI会用低质量素材填满所有位置——看起来"完整"，但观众一眼就能看出不协调。**质量阈值的价值不在于它选了多好的素材，而在于它拒绝了多少不够好的素材。**

### 7.3 三个ID的一致性

剪映草稿的三个ID（内容ID、元数据ID、根索引ID）必须一致——这是踩坑踩出来的硬规则。这个细节说明了一个通用规律：**自动化的难点往往不在主流程，而在边缘兼容性。**

### 7.4 "抄结构" vs "抄内容"

这套工作流的核心创新是**"抄结构"不"抄内容"**：

| | 抄内容 | 抄结构 |
|---|---|---|
| 侵权风险 | 高 | 无 |
| 平台识别 | 容易判搬运 | 无法识别 |
| 原创性 | 低 | 高 |

**recipe.json** 捕获的是"结构"（几个镜头、每个多长、什么顺序），而**不是**"内容"（具体画面、文字、音频）。这就是"抄爆款"不侵权的技术依据。

## 总结

这套工作流的核心价值不在于"AI能不能做出爆款"，而在于**把一个人从每天剪6条提升到30条**，把重复劳动从3小时压缩到20分钟。

> 1. **自动化解决的是"重复"，不是"创造"**：Codex替你跑完80%的机械步骤（拆解、匹配、对齐），你把精力留给最后的判断和打磨。
> 2. **置信度阈值（0.6）是质量控制的关键**：宁可留空，也不硬凑。一个缺失的镜头比一个不对的镜头更容易被修复。
> 3. **"抄结构"不"抄内容"**：recipe.json捕获的是节奏和顺序，不是具体画面——这是"抄爆款"不侵权的技术边界。
> 4. **封装为Skill是效率的最终杠杆**：首次搭建30分钟，日常使用5-10分钟。真正的杠杆来自"一次搭建，无限复用"。

> **一句话带走的实践原则**：把参考视频拆成结构数据（recipe.json），让AI按结构从你的素材库匹配视觉内容——"抄结构"不"抄内容"，5倍效率提升，0侵权风险。
