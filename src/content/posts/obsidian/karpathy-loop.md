> **一句话总结**：不要当 AI 的引擎——让 AI 自己在循环中跑，你只定义目标和验收标准。

---

## 1 · 什么是循环

### 提示 vs 循环

| | 提示 (Prompt) | 循环 (Loop) |
|---|---|---|
| **谁驱动** | 你，每一步 | AI 自己，直到完成 |
| **目标定义** | 每次都问 | 只定义一次 |
| **AI 角色** | 扳手，你拿起来放下 | 引擎，持续运转 |
| **比喻** | 2005 年的谷歌搜索 | 自动驾驶 |

### 循环三要素

| 要素 | 作用 | 缺失后果 |
|------|------|---------|
| **验证器 (Verifier)** | 客观判定结果是否达标 | AI 自己批改作业，自我确认 |
| **状态 (State)** | 记录已尝试/失败/下一步 | 每轮从零开始，重复同样的错误 |
| **停止条件 (Stop Condition)** | 目标达成 or N 次后停止 | 无限循环直到烧光预算 |

> **核心**：目的只定义一次，循环负责处理剩下的一切。

## 2 · 你真的需要循环吗？——四项前提测试

> 循环有代价。四项全部成立才值得，漏一个则成本大于回报。

```
┌─────────────────────────────────────────────────────┐
│              环路工程前提测试                          │
├─────────────────────────────────────────────────────┤
│                                                     │
│  □ 1. 重复频率 ≥ 每周一次                             │
│     一次性任务用好的 Prompt 即可                       │
│                                                     │
│  □ 2. 验证是自动化的                                  │
│     测试套件 / 类型检查器 / linter / 构建              │
│     没有自动检查 = 你又在看每一个 diff                 │
│                                                     │
│  □ 3. 代币预算能吸收浪费                              │
│     循环会重读上下文、重试、探索                       │
│     免费额度 → 明显划算                               │
│     $20 套餐 → 可能鲁莽                               │
│                                                     │
│  □ 4. Agent 有真正的工具                             │
│     日志、重现环境、能运行代码看报错                    │
│     没有这些 = 盲迭代                                 │
│                                                     │
│  四项全 ✅ → 值得构建循环                              │
│  漏任何一个 → 用好的 Prompt                           │
│                                                     │
└─────────────────────────────────────────────────────┘
```

> **诚实判断**：大多数人还不需要重循环。消费级套餐会在生产力提升到来前就触及费率上限。

## 3 · 卡帕西环路 (Karpathy Loop)

### AutoResearch — 三个文件，630 行代码

2026 年 3 月，Andrej Karpathy 发布 `AutoResearch` GitHub 仓库。一个月内 66,000+ star，《财富》杂志命名为「卡帕西环路」。

```
AutoResearch/
├── train.py        ← Agent 唯一能碰的文件（训练脚本）
├── prepare.py      ← 评分器（Agent 不能碰，防止自降标准）
└── program.md      ← 指令（探索什么、遵守什么约束）
```

### 循环流程

```
阅读代码 → 建议修改 → 训练 → 检查结果是否改善
                                    │
                              ┌─────┴─────┐
                              │  改善了？   │
                              └─────┬─────┘
                           是 ↙         ↘ 否
                      提交 (commit)     回滚 (revert)
                              ↘         ↙
                                重复循环
```

**关键设计**：人类从不触碰 `train.py`，只写 `program.md`。Agent 负责执行。

### 结果

| 实验者 | 运行时间 | 实验次数 | 成果 |
|--------|---------|---------|------|
| **Karpathy** | 2 天 | 700 次实验 | 发现 20 个他手工调参 20 年错过的改进点 |
| **Tobi Lutke (Shopify CEO)** | 一夜 | — | 质量提升 19%，模型体积缩小一半 |

**典型发现**：注意力机制中缺少一个标量倍数，导致注意力在各 head 之间分散。人类在第 12 次实验后会疲惫，Agent 不会。

### 核心见解

> 如果你有客观指标，就不应该由你来主持实验。**你是瓶颈**。把自己从循环中抽离。

## 4 · 循环的五个构建模块

> 每个工作循环——无论用 Claude Code、Codex 还是 bash 脚本——都由五个部件组成。

| # | 部件 | 作用 | 工具映射 |
|---|------|------|---------|
| 1 | **自动化 (Automation)** | 心跳：在计划/事件/触发点启动循环 | Claude Code: `/loop` `/goals` · Codex: 自动化标签页 |
| 2 | **技能 (Skill)** | 存储项目知识，避免每次从零推导 | Markdown 文件：惯例、构建步骤、历史教训 |
| 3 | **子代理 (Sub-agent)** | 制造者与审查者分离 | 写手：快速便宜 · 审稿人：缓慢严厉 |
| 4 | **连接器 (Connector)** | 在真实环境中行动 | 读 issue 追踪器、开 PR、ping Slack、更新 Linear |
| 5 | **验证器 (Verifier)** | 门：自动拒绝不良作品 | 测试、类型检查、构建 |

> 没有验证器 = 花钱让 Agent 整晚自言自语。

## 5 · 双层自研究——提升 5 倍

### 论文：《双层自动研究：元自我研究》(2026.03, arXiv)

核心问题：**如果自研本身就是一种研究形式——你能自研自研吗？**

### 双环架构

```
┌─────────────────────────────────────────────────┐
│  外环 (Meta-Loop)                                │
│  观察 → 识别内环卡在哪 → 生成新 Python 代码       │
│  改变内环的搜索方式 → 注入 → 让内环重新运行        │
│                                                   │
│  ┌───────────────────────────────────────┐       │
│  │  内环 (Karpathy 原版)                  │       │
│  │  提出变更 → 训练 → 评估 → 保留/弃用     │       │
│  └───────────────────────────────────────┘       │
└─────────────────────────────────────────────────┘
```

### 结果

| 指标 | 单环 (Karpathy) | 双环 (Meta) | 倍数 |
|------|----------------|-------------|------|
| val_bpb | -0.009 | -0.045 | **5x** |

不是好 5%，是好 **5 倍**。两个循环用的是同一个 LLM——改进来自架构，不是更聪明的模型。

### 外环发现了什么

内环不断陷入同样的搜索模式：LLM 对尝试哪些优化有先验偏好，即使那些优化已经失效，它也会反复回到这些先验。**外环打破了这些模式**，迫使模型向本能回避的方向探索。

> 论文结语：「如果自研究能够自我元研究，原则上它可以对任何有可测量目标的东西进行元自研究。」

## 6 · 立即试用——零工具循环

> 不需要 Claude Code 或 Codex，粘贴到任何 LLM 里即可体验核心机制：

```text
You will work in a loop until the task meets the bar.

TASK:
[describe exactly what you want produced]

SUCCESS CRITERIA (be strict):
- [criterion 1]
- [criterion 2]
- [criterion 3]

LOOP PROTOCOL, repeat every turn:
1. PLAN   - state the single next step.
2. DO     - produce or improve the work.
3. VERIFY - score the result 1-10 on each criterion.
            Be brutally honest. List exactly what is still weak.
4. DECIDE - if every criterion is 8+, print FINAL and stop.
            Otherwise print ITERATING and go again, fixing
            the weakest point first.

RULES:
- Never call it done until every criterion is 8 or higher.
- Each pass must fix the weakest score from the last VERIFY.
- Do not ask me questions. Make a sensible assumption
  and keep going.

Begin.
```

**循环四步**：PLAN → DO → VERIFY → DECIDE

> 限制：你仍是触发者，无持久状态，关闭标签页就消失。但它展示了核心机制。从这到完全自主循环 = 添加自动化 + 状态文件 + 验证门。

## 7 · 诚实部分——循环无法解决的问题

> 循环改变了作品。他们不会把你从里面删除。

### 两个会随流程变好而更尖锐的问题

**1. 理解债务 (Comprehension Debt)**

循环发布越快 → 你没写的代码越多 → 仓库内容和你实际理解的差距越大。平稳运行的循环对这个缺口收取**复利**。当你必须调试一个团队里没人读过的系统时，成本比代币本身还高。

**2. 认知投降 (Cognitive Surrender)**

循环自我运行时 → 容易停止形成观点 → 接受回应的一切。

- 设计循环 = 带着判断力的解药 ✅
- 避免思考 = 助燃剂 ❌

动作相同，结果相反。

### 关键区分

> 两个人可以构建完全相同的循环，却得到完全相反的结果：
> - 一个人用它来**更快地完成深刻理解的工作** ✅
> - 另一个人用它来**避免理解作品** ❌
>
> 循环分不清。你有。

**Karpathy 停止了写代码。Cherney 停止了提示。他们谁也没有停止思考。**
