## 30 秒答案

Anthropic 工程团队首次公开了 Claude 记忆系统的组成部分与架构。核心机制是**梦境整理（dreaming）**：

> 借用人脑「海马体离线重放 → 巩固到新皮层」的分工：Claude 在会话间空闲时，回顾日志、纠正错误笔记、构建新的记忆表征（如维基）、决定什么该预载入下次会话。

五个核心判断：

1. **记忆是对未来需求的预测**——写下一条规则，就是预测这个模式还会再出现
2. **只记「不写下来就会消失的东西」**——屏幕能读到的游戏状态不值得记（宝可梦实验：Fable 5 用 9 个文件拿了 4 枚徽章，Sonnet 3.7 用 413 个文件只拿了 1 枚）
3. **会话记录是记忆的事实底座**——错误笔记靠回查原始记录来纠正（月见山案例）
4. **强模型不需要固定记忆规则**——「只记录失败」反而损害 Opus 5 的表现；引导对老模型帮助最大
5. **顶层注入必须精简**——指令文件越长，遵循程度越低；Claude Code 只载入 MEMORY.md 前 200 行作为索引

## 二、记忆的四个组成部分

| 组成部分 | 机制 | 类比 |
|---------|------|------|
| **原始记录（日志/会话记录）** | 一切工作的完整留存 | 海马体的即时捕捉 |
| **记忆笔记（notes）** | 跨会话持久保存的文件/文件夹 | 长期记忆 |
| **知识组织形式（wiki 等表征）** | 互链页面构成的知识地图 | 新皮层中的结构化知识 |
| **自动载入上下文（顶层注入）** | 每次会话开始预载入的精简索引 | 工作记忆 |

分层原则：**顶层注入占用每次会话的 token，必须精简；下方各层在需要时才被读取或搜索。** Claude Code 的自动记忆只载入 MEMORY.md 前 200 行或 25KB，作为「它知道什么、去哪找」的索引。

> 载入一条笔记，不保证 Claude 会照做——指令文件越长，遵循程度就越低。

## 三、核心机制：梦境整理（dreaming）

源自 Letta 和 UC Berkeley 的「睡眠时间计算」（sleep-time compute）：让模型利用交互之间的空闲时间重新组织已有上下文。

梦境整理做五件事：

1. **纠正错误笔记**：将笔记与原始会话记录核对（月见山案例）
2. **构建新的记忆表征**：如维基——互链页面组成的知识地图
3. **维护顶层精简**：把细节移到下层，顶层只留链接
4. **围绕特定目标组织记忆**：调整记忆增长的方向
5. **补上单次会话留下的缺口**：跨会话发现断链、补页面

**为什么需要它**：Claude 写笔记时只能看到当次会话的上下文，无法看到全局模式；笔记也可能从一开始就是错的、或因环境变化而失真。梦境整理提供了**用原始记录校验笔记**的机制。

## 四、两个关键实验

### 4.1 CL-Bench 学习循环：模型的代际跃迁

任务：查询数据库回答问题，每次作答后获知正确答案，可以写一条记忆帮助后续问题。每个问题从全新会话开始，唯一例外是可读取持久记忆目录。

记忆支撑的学习循环：**答错 → 记录失败 → 提出假设 → 检验假设 → 把发现转化为规则。**

模型代际差异（谁完成了闭环）：

| 模型 | 记忆行为 |
|------|---------|
| Sonnet 4.6 | 只写未经检验的猜测，散落各处 |
| Opus 4.7 | 整合成参考文档，标注已核查/未确认 |
| Sonnet 5 | 评分器确认后标记「已确认」，答错写更正 |
| **Opus 5** | **第一个完成学习闭环**：每条规则 + 如何确定它正确 + 先前答案 + 陷阱提醒 |
| Opus 5.5 / Sonnet 5.5 | 完成闭环 |

### 4.2 宝可梦实验：什么值得记住

Sonnet 3.7 和 Fable 5 各玩一轮《宝可梦 红》，约 10,000 步时对比记忆文件夹：

| | Sonnet 3.7 | Fable 5 |
|--|------------|---------|
| 记忆量 | 225 文件夹、413 文件 | 2 文件夹、9 文件 + global.md |
| 进度 | 1 徽章 | **4 徽章** |
| 记了什么 | 一切：每场战斗、每件道具、每个 NPC——**包括屏幕上随时能读到的钱和位置** | 只记**游戏没有明确告诉它的**：策略、计划、已验证规则 |
| 后果 | 记录不断过时，花时间梳理记忆而非玩游戏（17 步内建 6 个文件删 9 个，零行动） | 记忆随游戏重写，最终通关 |

> **判断什么值得记的标准**：如果不写下来就会消失，就写；如果随时能从环境读到，就不写。

Fable 5 的记忆结构：`global.md`（信息面板：当前目标 + 预先写好的计划 + 记忆使用规则）、`locations/`（路线计划）、`gameplay/`（机制策略）。一条真实笔记：「如果连续 3 个或更多精灵球都失败，就改变操作时机（插入等待按键）——这样做后马上就抓到了。」——**一条从 7 次失败中提炼的可复现规则**。

## 五、三个关键教训

### 5.1 强模型不需要固定记忆规则

CL-Bench 上只告诉模型「有一个记忆文件夹」就足够让 Opus 4.7/5 有效使用。但设定「只记录失败」这条具体规则后，**Opus 5 和 Opus 4.7 都失去了记忆原本带来的很大一部分提升**。

> 对能力更强的模型来说，让它们自主判断信息的重要性，比预先设定固定规则更有效；这些规则反而可能削弱表现。

引导对**早期模型**帮助最大：Sonnet 4.6 经常不读记忆文件、不检验假设——提示「先读记忆文件、再明确检验假设」几乎使分数翻倍；Sonnet 5 不需要提示，十次里九次主动读。

**官方实践**：对前沿模型只给简单指引——「当用户要求记住某件事，或某件事明显值得记住时，创建记忆笔记」——具体判断交给模型。

### 5.2 会话记录是记忆的事实底座

月见山案例：Claude 错误记下「宝可梦中心在东侧」→ 宣布「月见山已完成」→ 实际没穿过 → 三次掉回原路 → 想放弃。梦境整理将笔记与会话记录核对 → 发现错误 → 重写笔记 → 直接穿过月见山到达华蓝市。

> 会话记录为 Claude 验证记忆提供了事实依据。没有原始记录的对照，错误笔记会被永久信任。

### 5.3 维基的价值取决于任务形态

Stainless 语料实验（35 万文件、4.2 亿 token、25 问题）：

- 128 次梦境整理会话后，满足评分标准的比例 **13% → 48%**
- **搜索 + 维基 = 最佳**：综合得分 54% → 61%（单搜索 53%，单维基 48%），每问题省约 20,000 token
- LAB 并购 24 问（需多文档整合 + 判断/计算）：维基 **87%** vs 搜索 73%
- 单文档就能回答的任务：维基无提升
- **博尔赫斯陷阱**：一个 LAB 任务中维基比原始文档还大——「他们绘制的地图过于详细，最后竟与地图所描绘的帝国一样大」——维基失去抽象作用，变成第二个语料库

## 六、深度思考：六个问题

**Q1：这篇与 Memory Tax 论文是什么关系？**
它几乎是 Memory Tax 的**官方答案**。论文发现：记忆系统的税来自保真度（证据丢失）、可及性（碎片化/稀释）、鲁棒性。Anthropic 的架构逐一回应：

| Memory Tax 的发现 | Anthropic 的答案 |
|------------------|-----------------|
| 证据在构建中丢失 | 梦境整理回查会话记录（src-aug 的流程化形态） |
| 记忆表征膨胀（博尔赫斯陷阱） | 顶层精简原则 + 「维基不能代替检索，要与搜索结合」 |
| 固定规则对强模型有害 | 「只记录失败」实验的正面结论 |
| 基准余量（RAG 已很强） | 会话记录搜索是记忆的**基础**，维基只是其上的一层 |

论文说「建模未来需求是方向」（7.3 节），Anthropic 直接说「**记忆是对未来需求的预测**」——两篇独立收敛到同一个结论。

**Q2：「记忆是预测」意味着什么？**
写一条规则 = 下注「这个模式会再出现」；写一个已验证事实 = 下注「未来的会话想直接用它而不必再核查」。这个视角把记忆从「存储」变成「**带风险的决策**」：每条笔记都是预测，预测错了就是 Memory Tax 论文里的税。所以记忆系统需要纠错机制（梦境整理）——就像预测系统需要校准。你知识库里的 Codex 与 Obsidian 知识沉淀协议 说「不默认归档临时问答」，本质上就是**降低预测基数**：只沉淀预测概率高的内容。

**Q3：「只记录失败」为什么损害强模型？**
这是 [Skill 自进化改造指南 - Agent 帮我进化，我只负责反馈](/posts/obsidian/skill-self-evolution-guide/) 的官方实证。指南说「避免规则无限膨胀」；Anthropic 给出数据：一条看似合理的固定规则，让强模型失去大部分记忆收益。原因在于**规则压缩了模型判断的空间**：强模型本来能分辨「什么值得记」，规则却把它锁死在一个维度上。这与 [GPT-6 Astra 技能与提示重审 - 指令减法的艺术](/posts/obsidian/instruction-subtraction/) 的「少写食谱」完全同源——**模型越强，固定规则越贵**。而老模型需要引导（Sonnet 4.6 分数翻倍）——规则的价值与模型能力负相关。

**Q4：宝可梦实验的「只记屏幕没有的」与 src-aug 矛盾吗？**
不矛盾，是同一枚硬币的两面。Memory Tax 论文的 src-aug 说「保留回源路径」——从**源历史**可以恢复的证据，不需要复制进记忆；宝可梦实验说「屏幕能读到的，不值得记」——从**环境**可以恢复的证据，也不需要记。合起来是一条更普适的原则：**记忆只存「别处不可恢复」的信息；一切可恢复的，都靠回查。** 这是注意力经济学在记忆层的应用：记忆的成本是维护与过时风险，只有不可恢复的信息才值得付这个成本。

**Q5：顶层注入与渐进式披露是什么关系？**
「顶层精简 + 下方各层按需读取」就是 [DeepSeek 超级代理设计 - 注意力经济学与领域模型](/posts/obsidian/deepseek-superagent-design/) 的「面板只显示需要人的东西」在记忆层的形态，也是渐进式披露的官方实现：MEMORY.md 前 200 行 = 索引（告诉模型它知道什么、去哪找），细节在下方。**注入层的唯一任务是路由，不是知识。** 这与 huashu-design 的路由式 SKILL.md 是同一架构。

**Q6：合同条款案例（57→41→57 事实）说明了什么？**
它演示了**记忆构建指令的进化循环**：失败（漏 16 项事实）→ Claude 反思失败原因 → 提出指令修改（每合同独立页面、逐字引用）→ 重建 → 100%。这恰好是 [Skill 自进化改造指南 - Agent 帮我进化，我只负责反馈](/posts/obsidian/skill-self-evolution-guide/) 的完整预演：**反馈 → 诊断 → 改造 → 验证**。而且失败根因是组织形态（共享表格互相覆盖），修复方案是改变分工而非增加文字——正是指南说的「优先修改工具和检查，而不是不断增加提示词」。

## 七、对你知识库的直接启示

这篇文章最特殊的价值：**你的 Obsidian vault 就是 Claude 的记忆系统的一次手工实现**，Anthropic 的架构为它提供了官方坐标系：

| Anthropic 架构 | 你的 vault 对应 |
|---------------|----------------|
| 会话记录（事实底座） | 与 AI 的对话历史、原帖原文 |
| 记忆笔记（预测未来需求） | 知识归纳 28 篇——每篇都是「这条模式还会用得上」的预测 |
| 维基（知识地图） | 知识归纳 索引 + 三个索引的交叉链接 |
| 梦境整理（回查纠正） | 「source 字段 + 原文引用」= 笔记的溯源路径 |
| 顶层注入（精简索引） | 索引文件的分类维度，而非全文 |

开放问题（Anthropic 自述未解决，也是你的机会）：**何时写记忆**（即时笔记分散注意力 vs 梦境整理延迟产出）——你的实践是「会话后沉淀」，属于梦境整理路线；**如何保持最新**——Anthropic 建议按访问频率决定整理频率，你的 vault 没有这个机制，未来可以给高频文章加「最近验证日期」。
