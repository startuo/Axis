## 30 秒答案

「自我提升记忆」正在快速成为持续学习代理的核心部件。截至 2026 年 11 月，Google、Meta、以及 RL 派的研究者给出了**三条路线**，回答的是同一个问题：

> **记忆的改进，应该存在哪里？**

| 路线 | 代表 | 改进存在于 | 一句话 |
|------|------|-----------|--------|
| **① 外部日志** | Google **SIM** | 优化器读的结构化日志 | 进化产物可迁移，理由必须随行；跨模型接力（Opus 5.5 → Gemini 3.8 Flash）不重来 |
| **② 权重内化** | Meta **Self-Improving Memory** | 模型权重（SFT + LoRA） | 模型自己发现记忆习惯，再训练进自己的权重；部署时通用提示就够 |
| **③ 强化学习** | **RIME** 等 | 学出来的记忆策略 | 不做提示搜索，直接 RL 训练"解题 + 写记忆"，奖励对未来任务有用的笔记 |

三者的取舍轴：**可迁移性 vs 推理效率 vs 学习深度**。外部日志最便宜、跨模型、可审查；权重内化推理时零开销、但绑定模型；RL 最通用、但需要奖励设计和训练设施。

## 一、Meta 路线：Discover → Demonstrate → Distill

### 1.1 问题动机

Meta 的起点是一个朴素观察：**没有一种记忆设计在所有任务上都最好。**

他们先在 CL-Bench（Continual Learning Bench）的三个任务（Database、Codebase、Spectrum）上做了小规模试点：用人工写的四种记忆策略（摘要、检索、技能库、假设追踪），每种由两个提示实现——

- **OFFLOAD**：子任务完成后，让代理把学到的东西卸载进记忆目录（**文中明确说这个过程 sometimes called dreaming**）
- **LOAD**：下个子任务开始前，加载相关记忆

结果：没有任何一种策略在三个任务上通吃。所以——**模型应该学习自己的记忆设计**。

> 注意这个设定与 Claude 记忆架构的呼应：每个子任务从全新会话开始、上下文清空，唯一跨任务的是持久化记忆目录。**OFFLOAD = 梦境整理的显式化**。

### 1.2 两阶段方法

**阶段一：Harness Optimization（发现）**

元优化回路，两个角色：

- **meta agent**：读任务代理的轨迹，分析哪里记忆用得不好，重写 LOAD/OFFLOAD 提示
- **outer loop**：评估候选 harness，用任务得分挑选最有希望的设计继续修订

具体搜索流程：

1. **初始化池**：4 个人工写的种子 harness（摘要/检索/技能库/假设追踪）
2. **评估**：每个候选跑完整任务流 N=5 次，产出轨迹、子任务得分、记忆目录
3. **选择**：按平均分排序，取前 P=4 作为父代
4. **分析与提案**：每个父代，meta agent 读消息历史 + 子任务得分 + 最终记忆目录，识别反复出现的失败，提出修订。因为轨迹长，它先摘要每个子任务 → 再分析整轮 → 最后跨轮整合证据
5. 迭代若干轮，选存活下来的最高分 harness

**阶段二：Harness Distillation（内化）**

1. **Demonstrate**：用最优 harness 在训练子任务上跑，记录每次 LLM 调用（提示、回复、推理、工具调用与参数、工具响应）
2. **关键操作**：把记录里优化后的 LOAD/OFFLOAD 提示**换回通用提示**——因为两者兼容（优化版指定了记忆设计，通用版把选择权留给模型），无需修正步骤
3. **Distill**：在换过的轨迹上做 SFT（遮蔽式下一 token 预测，只对 assistant token 计损失），LoRA rank 64 作用于注意力投影层

**为什么换回通用提示？** 训练目标是让模型在**通用 harness** 下也能表现好——技能要脱离脚手架、内化进权重。这正是「提示 → 权重」的迁移。

### 1.3 数据

模型：Kimi-K2.6 同时充当 meta agent 和 task agent——**模型训练的是它自己发现的记忆技能**。

| 指标 | 结果 |
|------|------|
| 优化 harness vs 最佳人工种子 | **56.0 vs 44.6（+11.4）** |
| 优化 harness vs 通用 harness | **56.0 vs 36.1（+19.9）** |
| 三个任务全部提升，最大提升在 Codebase | **+20.6** |
| 蒸馏后（通用提示下）vs 在通用轨迹上 SFT | **43.1 vs 37.6（+5.5，14.6%）** |
| 蒸馏后 vs 不做 SFT | 43.1 vs 36.1（+7.0） |

### 1.4 最值得记的细节：搜索的绝大多数提案是失败的

> 在完成的搜索中，**44 个生成的修订里有 37 个没能打败此前迭代的最好成绩**。

Database 和 Spectrum 在第一代搜索就达到 53.8 和 49.9，之后再无提升；Codebase 到第四代才升到 64.3。

**结论：进步依赖评估与选择，而不是提案本身。** 这句话是整篇博客最重要的工程教训——与 Memory Tax 论文的「先跑最蠢的 baseline」、与「只保留得分更高的」是同一条纪律。

### 1.5 案例：Codebase harness 的进化

| 版本 | 分数 | 诊断 → 修订 |
|------|------|-----------|
| Summary 种子 | 34.3（通用 33.5，最佳种子 43.7） | 报告指出：单体笔记膨胀、反复重新发现仓库结构 |
| 修订一 | **52.2** | 复用记录过的路径 + 保留失败规则 |
| 修订二 | **55.7** | 报告诊断「只追加不索引」→ 紧凑 quickstart + 带索引的 registry + 分开的修复文件 |
| 另一分支 | 36.6 | 只保留最近两次修复的细节 → 失败（丢失长期经验） |

## 二、三条路线的完整对照

### 2.1 Google SIM（路线①：外部日志）

优化器读失败追踪 → 编辑提示/工具/检查 → 测得分 → 保留更好的。SIM 是给**优化器本身**的结构化日志：每条目按问题根因分组，记录①修改及理由 ②测试前预测 ③实际修复（含失败）④测试模型与基准。

跨模型接力：Opus 5.5 进化完 → Harness + 完整 SIM 交给 Gemini 3.8 Flash 继续。工作区 84.75 vs 73.42；Coding 10 次里 9 次更好（+2.36，p=0.003）。详情见 [RSI 与自我提升记忆 - Harness 自修复的闭环](/posts/obsidian/rsi-self-improvement-memory/)。

### 2.2 Meta Self-Improving Memory（路线②：权重内化）

搜索记忆中使用的提示（LOAD/OFFLOAD）→ 选出最优 → 用它的轨迹 SFT 进权重。**改进从「外部提示」迁移成「内部习惯」**，部署时通用提示即可。

### 2.3 RIME（路线③：强化学习）

跳过提示搜索，直接 RL 训练模型：同时学「解题」和「写记忆」，**奖励那些对未来任务有帮助的笔记**；还训练模型主动探索以收集有用信息（学习何时/探索什么）。需要 RL 训练设施与奖励设计。

### 2.4 对照表

| 维度 | ① 外部日志（SIM） | ② 权重内化（Meta） | ③ RL（RIME） |
|------|------------------|-------------------|-------------|
| 改进存于 | 日志文件 | 模型权重（LoRA） | 策略（权重） |
| 训练成本 | 无（只推理） | 中（SFT） | 高（RL + 奖励设计） |
| 推理开销 | 需读日志进上下文 | **零**（通用提示即可） | 零（行为已内化） |
| 跨模型迁移 | **天然支持** | 不支持（模型绑定） | 不支持 |
| 可审查/可回滚 | **高**（读日志） | 低（权重不透明） | 低—中 |
| 改进粒度 | 针对具体模型的具体失败 | 任务级记忆策略 | 通用记忆行为 |
| 适合谁 | 用第三方模型的应用层 | 拥有可控模型微调能力的团队 | 有 RL 基建的实验室 |

## 三、深度思考：五个问题

**Q1：三条路线实际在回答同一个问题——「改进应该存在哪里？」**
这正是 [Memory Tax 论文精读 - 记忆系统的净价值与记忆税](/posts/obsidian/memory-tax-paper/) 讨论的「记忆形态」（external store vs parametric）在**进化层面**的复现。外部日志 = 非参数化、可读可改；权重内化 = 参数化、快但难审；RL = 学出来的行为。选择不是技术优劣，而是**你要的权衡**：跨模型可迁移 vs 推理零开销 vs 学习深度。

**Q2：Meta 的 OFFLOAD 与 Claude 的 dreaming 是什么关系？**
同一个机制的两层实现。Claude 的梦境整理是**运行时**的记忆整理（会话间回顾日志、纠错、建 wiki）；Meta 把「如何整理」变成**可搜索、可训练的对象**——先用 OFFLOAD 提示显式指定策略（如建 REGISTRY.md、SCHEMA.md），再把策略蒸馏进权重，让通用提示也能触发。**Claude 研究「怎么整理记忆」，Meta 研究「怎么让模型学会整理记忆」。**

**Q3：44 个修订里 37 个失败说明了什么？**
说明「自动优化」的价值不在生成提案，在**评估与淘汰**。这也解释了 SIM 为什么记录失败——外部日志路线把「失败」保存为知识，Meta 路线把「失败」直接淘汰。两者合起来：**进化的核心是选择机制，不是想象力。** 这与「benchmark headroom」、与「只保留得分更高的」、与你 Playbook 里的「只审查高爆炸半径」是同一条纪律。

**Q4：为什么蒸馏时要换回通用提示？这对个人意味着什么？**
换回是为了「技能脱离脚手架」——训练目标是通用 harness 下也能做对，等价于把提示里的知识压缩进权重（context distillation）。对个人/团队的启示倒过来：**如果你没有权重，就把「好的提示/检查/工具」当成永久资产**——SKILL.md、AGENTS.md、检查脚本就是路线①的资产。两者在「知识沉淀」上是同一个动作的两个阶段：先沉淀成外部文件（低成本、跨模型），等某个技能高频稳定后再考虑内化。

**Q5：你该从哪条路线开始？**
按门槛排序：**① 外部日志 → ② 权重内化 → ③ RL**。路线①零训练成本、跨模型可迁移、可审查——SIM、Skill 库、你的 Obsidian 全在这条路线上；路线②需要模型微调能力，回报是推理零开销与「通用提示也够用」；路线③需要 RL 基建，适合把记忆策略当作核心研究对象的团队。**先做外部日志，把失败变成可回放的证据；当证据足够多且模式稳定，再谈内化。**

## 五、相关研究方向（Omar Sar 线程补充）

- **Continual-ARC**：持续学习基准
- **自适应记忆选择**：让代理学会选记忆
- **MemCredit**：记忆的信用分配
- **LLM 代理能自行组织内存吗**：自组织记忆的可行性研究

## 六、一句话带走

> 三条路线都在回答「改进存放在哪里」。**但无论存放在日志、权重还是策略里，能救你的永远是同一件事：保留理由、能评估、可回滚。** 没有评估的自我提升，只是更快的自我重复。
