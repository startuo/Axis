## 30 秒答案

长期记忆是长程代理的核心组件，但**「建记忆」相对「直接从原始历史检索」的净价值，一直没人算清**。这篇论文（UIUC 等五机构，2026-10）做了大规模评估，结论令人警醒：

> 许多精心设计的记忆系统，在多数情况下**打不过 naive RAG**——净价值为负。

论文把净价值拆成两个可度量的量：**Memory Benefit（记忆收益）**与 **Memory Tax（记忆税）**。

- **收益**：记忆解决了 RAG 漏掉的 query——重组事实、蒸馏偏好确实有时有用
- **税**：记忆弄丢了 RAG 本已解决的 query——证据被删除、遮蔽或变得难以获取

记忆的本质被重新定义：**不是纯粹有益的增强，而是一把双刃剑**——任何非平凡的记忆操作都构成对原始历史的偏离（deviation），偏离本意是服务任务，但某些设计选择会产生意外的有害效果。当税超过收益，记忆就不如直接检索。

税的三个来源（系统侧）：**保真度**（信息在构建中丢失/扭曲）、**可及性**（证据保存了但碎片化/稀释/改写后检索不到）、**鲁棒性**（模型依赖的操作放大跨骨干方差）。评估侧还有一个隐藏因素：**基准余量**——很多基准本身就是 retrieval-friendly 的，RAG 已经解决了大部分 query，重记忆系统没有收益空间，税就格外显眼。

三条设计启示（不引入新架构）：**让偏离可恢复**（保留回源历史的轻量路径，src-aug 实测把 SimpleMem 的税从 12.0 降到 5.2）、**让记忆记住它怎么记忆**（递归自指记忆）、**建模未来需求**（把记忆看作隐式推荐系统）。

## 一、论文信息与核心问题

| 项 | 内容 |
|----|------|
| 标题 | *Memory Tax: Dissecting the Net Value of Agent Memory* |
| 机构 | UIUC、清华、人大、Verdent.ai、Waterloo |
| 发布 | arXiv:2610.34073，2026-10-25，36 页 |

核心问题一句话：**What is the net value of memory over a straightforward baseline like naive RAG?**

论文指出的行业怪象：大量记忆系统的工作**只和其他记忆系统对比**，naive RAG 要么被忽略、要么设置不完整。没有检索基线，「建记忆的价值」和「直接检索证据的价值」纠缠不清——边际价值从未被检验。

## 二、实验设计：一次公平的清账

**基准**：LongMemEval-s、PersonaMem-v2（20%）、MINT-Eval（10%），分层抽样覆盖题型。

**骨干**：Qwen3.5-4B、Qwen3.6-27B、GPT-5.6-luna(low)；嵌入统一 Qwen3-Embedding-0.6B；裁判 Qwen3.6-27B LLM-as-Judge。

**11 个记忆系统按组织方式分四类**：

| 类别 | 系统 |
|------|------|
| Flat store | A-Mem、SimpleMem、MemOS |
| Hier/Lifecycle | MemoryOS、LightMem、OpenViking |
| Graph-based | HippoRAG2、PlugMem、MAGMA |
| Trained policy | Mem-T、Memory-R2 |

**公平性的关键设计——Retrieval Scope (RS)**：不同系统的记忆粒度和存储容量差异巨大，固定 top-k 会暴露不同数量的信息。论文调 top-k 使各系统暴露给 LLM 的记忆 token 量与 RAG 相当。这堵死了「记忆系统只是检索得多」的解释路径。同时报告 token 成本、端到端时间、LLM 调用数、存储大小。

## 三、核心发现：naive RAG 的统治力

主表（Table 1）最刺眼的一列：**几乎所有系统在 LongMemEval-s 上落后 RAG(2rd)**，差距随骨干增强而扩大（如 GPT-5.6-luna 上 A-Mem −6.0、MemOS −12.0、MAGMA −14.0、OpenViking −27.0）。OpenViking 在 4B 上 −40.4，堪称灾难。

正收益零星出现：MemOS 在 PersonaMem-v2 上 +1.0/+1.5（Qwen 骨干）、PlugMem +3.3、Mem-T +3.9（MINT-Eval + luna）、Memory-R2 +2.0（PersonaMem + 4B）。**没有任何系统稳定打败 RAG**。

Pareto 图（准确率 × token 成本，气泡 = 存储大小）更直接：多数记忆系统**又贵又低**。

两个值得注意的细节：

- **每 query 对比的韦恩图**：记忆确实解决了 RAG 漏掉的 query（收益），但也弄丢了 RAG 已解决的 query（税）。记忆不是均匀变差——它**换了一批 query 会做**。最终成绩取决于换来的多还是丢的多
- 反直觉现象：PersonaMem-v2 上 GPT-5.6-luna 全面低于 Qwen3.6-27B，与其他基准相反——更强的模型不一定更适合记忆任务

## 四、记忆税的三个来源（系统侧）

### 4.1 保真度：信息活过了构建吗？

记忆操作（重组、压缩）会在**检索开始前**丢弃或扭曲证据，这种损失之后无法恢复。

- **宏观**：只给 gold memory units 重放 QA（消除检索失败），残余损失 = 构建损失
- **微观**：采样原子事实追踪到记忆单元，标注损失程度。结果：MemOS 85.8% 无损失，**OpenViking 只有 39.4% 无损失、38.0% 直接没有对应记忆单元**——它在构建阶段就把证据扔了

> 信息损失是记忆税的直接原因。

### 4.2 可及性：保存了，但够得着吗？

MAGMA、LightMem 的 gold-memory 分数接近 gold-raw-turn 分数，却远高于其原始分数——**证据在库里，但正常检索够不着**。

微观案例揭示三个反复出现的模式：证据**碎片化**（散落在多个记忆单元）、**稀释**（与无关信息混在一起）、**改写**（措辞改变削弱 query 对齐）。相似度分布整体漂移 + 逐点对比都证实：记忆构建系统性地降低了同一证据与 query 的对齐度。

> 记忆过程通过碎片化、稀释、改写降低证据可及性，制造税——**即使证据没有丢**。

### 4.3 鲁棒性：换个模型还成立吗？

长寿命代理会用一个模型建记忆、另一个模型消费记忆。交叉实验发现：

1. 固定 QA 模型，换构建模型 → 分数明显波动（预期内，中间操作依赖骨干）
2. **更值得注意的是**：固定构建，换 QA 模型 → 许多记忆系统的分数波动**大于 RAG**——记忆机制在原始历史检索之上引入了额外脆弱性

> 记忆过程放大骨干敏感性：模型依赖的操作给原始历史注入了额外方差。税不仅是性能点的损失，还是鲁棒性的损失。

## 五、评估侧：基准余量（Benchmark Headroom）

在更广的基准集上跑极简基线：No Memory、IDF-keyword（词法匹配）、RAG-Emb、RAG-Hybrid。结果：**IDF-keyword 在一些基准上能拿 50%+，RAG-Hybrid 约 70%**——很多广泛使用的基准相当 retrieval-friendly。

当 RAG 已经解决了基准的大部分 query，重记忆系统**没有空间提供收益**，而它引入的哪怕微小损失都变得显眼——税被放大。这解释了为什么轻量设计（甚至无显式构建）能表现强劲：**它们「继承」RAG 的强基线，只引入很少的税**。

论文的评估建议：报告记忆系统时应同时报告 naive RAG 分数——把剩余改进空间显式化；RAG 分数本身可作为校准基准难度的参照。

## 六、泛化：记忆税不止于个人助理记忆

**经验记忆**（ALFWorld/WebShop/Mind2Web/BigCodeBench/AppWorld/τ²-Bench）：效果随任务域变化——Web 任务中把长轨迹蒸馏成工作流可超过 RAG；工具使用上几个记忆方法落后 RAG。**税的大小强烈依赖任务设置**。

**世界模型记忆**（Context-as-Memory、MemoBench 的长程一致性）：直接检索并重新注入过去观测（naive frames）取得**最强一致性**；latent/KV cache 记忆不一致地落后——额外记忆操作引入的损失抵消了预期收益。

> 记忆税的概念跨记忆形态和场景成立：任何非平凡的记忆操作，都可能同时引入有益的偏离和有害的偏离。

## 七、设计启示：不引入新架构的补救

论文刻意排除常见的 test-time scaling（检索加深、query 精化、更强模型），只谈现有系统可用的简单改动：

### 7.1 让偏离可恢复（构建侧）

既然有害偏离难以彻底消除，更可行的方向是**让它可恢复**——当记忆不够用时，保留一条回到源历史的轻量路径。证明概念（src-aug）：从源历史检索 + 正常记忆检索联合 rerank 再做 QA。结果一致改进，税大幅下降：

| 系统 | LongMemEval-s Acc | Tax | +src-aug Acc | Tax |
|------|-------------------|-----|--------------|-----|
| SimpleMem | 73.6 | 12.0 | **82.8** | **5.2** |
| MemoryOS | 73.4 | 11.4 | 76.4 | 7.8 |
| Mem-T | 75.0 | 10.8 | **80.0** | **5.2** |

PersonaMem-v2 上同样显著（Mem-T 42.1→49.0，tax 15.2→8.7）。**一条回源路径，几乎砍半了记忆税。**

### 7.2 让记忆记住它怎么记忆（访问侧）

受递归自我改进（RSI）启发：**memory can "remember how it remembers"**。过去的 query、证据、检索路径本身成为记忆的材料——深层检索找到的证据，下次相似需求可以直接访问。这也打开了 test-time scaling 的新维度：**跨 query 的扩展**，不止单 query 内。实测有效但弱于 src-aug。

### 7.3 建模未来需求（未来方向）

AoT（提前构建）不知道未来 query 会是什么，被迫更精细地处理更多信息 → 越来越贵；JiT（即时构建）知道 query 后可以定向偏离，但把计算挪到在线、增加用户敏感延迟。中间地带：**建模未来需求**——个人代理场景中 query 不是纯随机的，过去的兴趣、习惯、访问模式构成先验。

> 从这个视角看，**记忆可以部分地看作一个隐式推荐系统**：估计过去信息对未来的相关性，把构建努力花在更可能被需要的地方。

## 八、深度思考：五个问题

**Q1：记忆税概念的迁移价值有多大？**
极大，它适用于**一切信息组织系统**。任何「从原始材料提炼出整理形态」的操作都是 memory construction，都引入偏离。笔记、摘要、文档、知识库、代码注释——全都有税。判断标准可以直接搬用：**偏离是否可恢复？**（有没有回源路径）**证据是否被碎片化/改写？**（整理后还能不能定位原始证据）

**Q2：为什么 naive RAG 这么难被超越？**
因为它在三个维度同时占优：**无损**（不处理 = 不丢证据，保真度满分）、**确定**（无模型依赖操作，鲁棒性满分）、**直接**（无组织改造，可及性满分）。记忆系统的每一步「智能」操作都是一次赌注：赌收益 > 税。论文的教训是**多数系统赌输了**——这和对 LLM 提示词的理解同构：在强基线上做最小偏离（呼应 [GPT-6 Astra 技能与提示重审 - 指令减法的艺术](/posts/obsidian/instruction-subtraction/) 的「少写食谱」、[DeepSeek 超级代理设计 - 注意力经济学与领域模型](/posts/obsidian/deepseek-superagent-design/) 的「少概念、少设置」）。

**Q3：src-aug 的设计哲学本质是什么？**
**任何智能处理都要保留回退路径。** src-aug = 记忆检索 + 原始检索联合 rerank = 记忆层的「安全网」。这与你知识库里反复出现的同一哲学共振：图工程的「升级路径」（不可修复→交给人类）、SuperPlane 的「重试上限 + 人工升级」、DeepSeek 的「按影响停止」、十五条的「证据优先」。四个场景、同一个模式：**智能层可以激进，但必须保留确定性的退路。**

**Q4：这篇论文对「你自己的知识库」意味着什么？（自我指涉）**
这个 Obsidian vault 就是一个记忆系统，我写的每一篇沉淀文章都是一次 memory construction——每一次都引入了偏离。照论文的诊断框架自查：

- **保真度**：每篇文章的 `source` 字段、原文引用、代码块保留 = 证据没有丢（对比 OpenViking 的 38% NU——如果沉淀时丢弃来源，就是 NU）
- **可及性**：知识归纳 索引 的分类维度 = 检索路径；碎片化风险 = 同一主题散落多篇（如代理工程分散在 8 篇）
- **鲁棒性**：文章跨模型可读（是给人读的，不受骨干影响）
- **src-aug 实践**：Codex 与 Obsidian 知识沉淀协议 里「不默认归档临时问答」的分工——**线程是 raw history（RAG 层），Obsidian 是 constructed memory（记忆层）**——这正好是论文推荐的分层架构：记忆层负责收益，原始层负责兜底

**Q5：benchmark headroom 给了什么通用教训？**
**评估任何系统之前，先跑最蠢的 baseline。** 论文的 IDF-keyword 能拿 50%+，十五条的「单代理循环错误分类一半失败」、SuperPlane 的「手卷脚本极具灵活性」——同一个道理：你不知道复杂方案有多少空间，直到你知道简单方案能拿多少。**朴素基线的分数 = 复杂度的上限。**
